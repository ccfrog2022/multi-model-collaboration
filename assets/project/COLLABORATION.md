# 项目协作规则

本项目以协调、实现、独立测试和审查组织开发。所有任务采用同一套角色和验收原则。

## 角色

- coordinator：主会话，负责需求、方案、任务记录、派发、源码和证据阅读、验证与最终验收。
- executor：按具名文件范围完成实现，返回实际改动与验证结果。
- tester：使用独立实例检查需求和实现，编写或执行测试，返回可复现结果。
- reviewer：只读检查方案或成果，给出发现与裁决。
- probe：只读验证工具入口和本地能力。

协调者统一安排模型调用、集成与提交。工作实例完成本次任务后回传结果；每次调用采用新的实例身份与独立工作会话。

## 任务与审查

协调者确定目标、范围、真实授权、验收条件及等级理由。普通任务完成实现和独立测试，由协调者逐项验收；重要任务在实现前进行独立方案审查，在测试后进行独立结果审查。

方案与结果审查分别绑定当前 SHA256。reviewer 的最终非空行采用 `COLLAB_VERDICT: PASS`、`COLLAB_VERDICT: PASS WITH NITS` 或 `COLLAB_VERDICT: FAIL`。有细节问题时提供 Findings，协调者逐项记录非阻断裁决。记录 FAIL 后任务进入 blocked；协调者通过 Rework 开始同一任务的新修订，按修复内容安排实施或沿用有效实现，独立测试并按任务等级审查当前结果。方案变化时提交 PlanFile 并重新审查方案。目标、等级或文件范围变化时创建关联任务。

仅需补充验证或修正测试文件时，Rework 可提供 ReuseImplementationFrom。运行时核对方案修订、实现者文件及原始调用证据，保存实现来源后进入 validating；独立测试、验收及必要结果审查重新执行。普通调用失败通过 Handoff 完成续作、独立测试、新验收及必要审查后，可直接 Complete 当前修订；在 Complete 前发现具体的新一轮补测问题时，可沿用未变化的实现。已完成任务的新问题创建关联任务。实现变化、失败仍待处理或经过 RecoverTask 的异常采用完整返工。

## 范围、备份与当前证据

实施前捕获受影响文件原件与元数据。`AllowedPath` 和每次调用的 `WritePaths` 列出具体文件，冻结测试保持稳定。调用前后分别检查项目文件库存与协作控制快照；项目配置中声明的派生目录按扫描规则处理。

任务验收采用当前实现对应的独立测试、审查和证据。RecordAcceptance 将提交文件保存为独立验收副本，记录来源与摘要；测试产物后续更新时，历史引用保持对应副本。旧版记录直接引用源报告时，在原路径保留旧原件，将新报告输出到已授权的新路径或任务 inbox 后登记。需要真实用户工作流时，记录当前版本的实际验证。

Handoff 保存交接前调用与证据边界，重置当前验收、真实流程验证和签署。连续交接核验并保留此前成功的角色接续，原件、方案和对应文件摘要有效时继续使用；待处理失败交给相应角色。每次交接后取得独立测试、新验收和必要结果审查，满足条件后 Complete。原始失败记录持续保留。

## 工具与沟通

项目工具表定义可用入口、角色能力、模型参数和调用偏好。工具就绪后按任务选择，同一项目受管调用串行执行。

派发正文与工作实例回传使用英文，用户交付使用中文。按角色提供必要材料，稳定背景引用权威文件，返工补充变化、位置、影响、复现证据及预期结果。PrepareContext 将本轮说明、引用摘要和前序调用整理为角色交接包；Invoke 使用返回的 ContextId。派发写明本次完整交付、验收依据和阻断条件。工作实例完成相关工作与检查后回传；后续复查由相关改动、失败或证据冲突触发。实际问题沿用简短 ID，关联处理结论、证据和独立复验结果。

## 异常与交接

### 修复阈值与停止条件

协调者在现有问题清单与交接材料中，按同一问题 ID 记录尝试、验证证据和连续无进展轮数。一次修复尝试及其结果核验计一轮；尝试因工具或环境阻断而结束时，也记录该轮结果。Handoff、Rework、更换模型或创建关联任务均延续原问题记录。

实质进展须有证据：失败范围缩小、阻断条件解除，或获得支持不同修复方案的新诊断。仅修改文件、重述结论、更换模型或重复相同失败不算进展。有实质进展时重新计算连续无进展轮数，保留既有记录。

同一问题连续两轮无实质进展时，协调者停止该问题相关的自动派发，完成当前进程清理与证据保存，向用户说明问题 ID、两轮尝试及结果、阻断原因、继续所需条件和可选路径。后续按用户明确的继续指示恢复派发，并说明下一次尝试的依据与验证目标。未满足的验收项保持未通过。

非阻断建议记录裁决或待办，不触发 Rework 或额外修复派发；验收满足且阻断问题关闭后交付。阈值由协调者结合验证证据执行。

### 异常处理

调用失败时保留日志和产物，核验进程清理并检查半成品。handoff_required 状态满足条件后由 Handoff 保存交接记录并切换阶段，遗留锁通过 RecoverLock 核验。failed_closed、清理未知与未决违规由协调者处理现场并准备证据，再通过 RecoverTask 核验恢复，随后 Rework 开始新修订。

完成前核查任务自建进程与浏览器，读取原始输出和源码，逐项签署验收结果。

## 角色文件与异常恢复

创建任务时用 TesterWritePath 指定 AllowedPath 中的测试与测试产物文件。执行者维护其余具名文件；测试者独立维护所指定的测试文件，发现实现问题后交回协调者安排返工。冻结测试保留原件。

RecoverTask 根据调用、违规、当前摘要和处理报告核验进程退出、越界文件恢复与备份，追加有效恢复记录。随后用 Rework 开始新修订并重新取得质量证据。项目库存与协作控制快照分别检查项目文件和历史协作记录，配置派生目录排除时保留任务文件和冻结测试检查。

启动前扫描完成后保存调用及绑定基线；启动后扫描中断通过基线重做范围核验。Handoff 与 Rework 沿用有效恢复记录判断历史清理状态。文件职责核对别名冲突和具名写入授权，控制快照保留大小写不同文件。RecoverLock 使用操作系统句柄互斥，Status 分别显示项目锁与恢复互斥占用。
